## How to run this

1. **Read `REFACTOR_PLAN.md` §1.2.1 first.** The seven owner resolutions `R-01`–`R-07` are commitments, not defaults, and every implementation plan depends on them.
2. **Work one task at a time.** Each task is self-contained: the task text plus the small file list in its `Context to Read` is everything the executor needs. It should not scan the repository.
3. **Approve per phase, not per task** (`R-07`). At 70 tasks, a per-task `APPROVED: EXECUTE` would be 70 approval cycles; pre-authorise the mechanical steps inside a phase during that phase's dry run.
4. **Do not skip a phase exit gate.** Each one can absorb an indefinite pause without leaving the tree broken — that is what makes this stoppable.
5. **`P0-T01` runs first, always.** Nothing else can be trusted until the baseline records which tests are already red.

## The five things most likely to go wrong

Each is defended by a specific task; these are the ones worth knowing before you start.

**The migration ledger bricks the database.** Twelve of the fourteen Python packages own a `migrations/` directory, and `AGENTS.md` §5 currently makes a checksum mismatch block *all* database access. Removing any migration-owning feature would therefore brick the DB rather than degrade. `P1-T01` amends §5 with owner-absent tombstones **before any code is written**, and `P8-T03` implements the classifier that makes it real.

**Config-disable is not deletion.** Disabling a provider only proves removability while no module registers itself at import time and no stale `sys.modules` entry masks the coupling. Three defences: the import-time side-effect lint (`P16-T03`), the fresh-interpreter physical deletion proof (`P11-T03`), and the rule that a stale module entry is a *failure*, not a pass.

**A formula changes while being moved.** The pilot copies `_wilder_rsi` character for character. The golden baseline captured in `P8-T05` and the `1e-9` parity gate in `P8-T06` are what turn "output unchanged" from a claim into a build failure — and no task may regenerate the baseline to make a test pass.

**A capability id gets invented.** `PROFILE_REQUIRED_CAPABILITIES` and `REQUIRED_PROVIDER_IDS` both ship empty and stay empty until `P12-T04`, whose first step enumerates `app/capabilities/` and whose tests assert every populated id has a spec file on disk. Writing `risk.kill_switch.v1` before Risk has migrated would cite an artefact that does not exist.

**All cycles get forbidden.** Cycles among `fail_closed` edges must raise; cycles through a `degrade` or `skip` edge are the Cordis idiom and are legal. `P4-T06` and `P16-T02` each carry a dedicated test asserting the optional-edge cycle is **not** flagged, because "reject every cycle" is the natural mis-implementation.

## Conventions every plan shares

- **Commands** come from `pyproject.toml`, `.pre-commit-config.yaml`, `scripts/ci_check.py` and `AGENTS.md` §7. None is invented.
- **`scripts/*.py` must be direct children of `scripts/`** — the ruff per-file-ignore glob (`INP001`, `D100`, `D103`, `ANN`, `T201`) matches only direct children, so a file in a subdirectory fails the lint gate.
- **`mypy --strict` and full ruff docstring rules apply to `app/`** but not to `scripts/`, which is excluded from type checking and not measured by coverage.
- **Coverage is global** (`--cov=app --cov-fail-under=80`), so a task adding production code without tests reddens the whole repository. Every task carries its own tests for this reason.
- **CHANGELOG:** one concise `## [Unreleased]` bullet per task, except tasks whose only outputs live under `docs/dev/`.
- **`app/kernel/`, `app/capabilities/` and `app/composition/` are non-feature infrastructure** — no `FEAT-*` ids, no Feature Registry sections, no numbered usage programs. Verified by architecture tests instead (`P1-T04`).
