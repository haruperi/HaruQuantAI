Each returns violation strings; `main` prints them grouped and exits 1 if any list is non-empty.

`check_no_import_time_io` flags a module-level call to any name in `FORBIDDEN_IMPORT_TIME_CALLS: Final[frozenset[str]] = frozenset({"connect", "open", "start", "subscribe", "register", "run", "Session", "Client"})` inside a provider package — the rule that makes config-disable honest.

### 3.4 `scripts/manifest_lint.py` — CREATE

```python
def check_requires_resolve(manifests, specs) -> list[str]: ...
def check_no_required_cycles(manifests) -> list[str]: ...
def check_no_internal_reach(repo_root: Path) -> list[str]: ...
def check_selection_determinism(manifests) -> list[str]: ...
def main() -> int: ...
```

Frozen rules: every `requires` resolves to some `provides`; no cycle among `fail_closed` edges (**cycles through `degrade`/`skip` are legal**); no provider imports another provider's internals; two enabled providers of an `exactly_one` capability is a violation.

> This is the replacement for the static import audit. Once coupling lives in capability strings, no linter checks a string — this script is the thing that does.

### 3.5 `app/composition/reconcile.py` — CREATE

```python
@dataclass(frozen=True)
class ReconciliationPlan:
    """What a configuration change requires, before anything is applied.

    Attributes:
        to_deactivate: Provider ids to stop, in reverse activation order.
        to_activate: Provider ids to start, in dependency order.
        unchanged: Provider ids untouched by this change, sorted.
    """

    to_deactivate: tuple[str, ...]
    to_activate: tuple[str, ...]
    unchanged: tuple[str, ...]


def plan_reconciliation(current: LoaderConfig, desired: LoaderConfig,
                        report: ResolutionReport) -> ReconciliationPlan: ...
def apply_reconciliation(root: CompositionRoot, plan: ReconciliationPlan,
                         config: Mapping[str, Mapping[str, object]]) -> tuple[str, ...]: ...
```

Frozen rules: `to_deactivate` is in reverse activation order; `to_activate` in dependency order; a failure during activation rolls the whole plan back by deactivating everything it activated; `apply_reconciliation` returns the failure names and never leaves a partially-applied plan.

**Tier 1 only.** Tiers 2 and 3 are documented in `P17-T02` and implemented by no task in this plan.

## 9. PLANNER OBSERVATIONS (non-blocking)

1. **Phase 12 has no wave tasks by design, and this is the honest outcome.** The source document generates the order from the audit; the audit runs during execution. A planner writing "Wave 7: strategy, 22 features, in this order" today would be inventing a dependency graph it has never seen.
2. **`P12-T02` produces a template, not documentation.** Its output is a fill-in work order with the same field set as every task in Batches 1–5, so a wave costs a read plus a fill, not a redesign.
3. **`architecture_lint` and `manifest_lint` are the point of no return.** After the waves, imports stop telling the truth about coupling. These two scripts are what replaces the AST audit, and they must exist before the waves, not after.
4. **`FORBIDDEN_IMPORT_TIME_CALLS` is heuristic and will produce false positives.** It is scoped to provider packages and module scope only, and `P16-T03` gives it an explicit allowlist mechanism rather than pretending it is exact.
5. **Phase 17 Tier 1 is genuinely cheap** because it reuses the Phase 5 and 6 machinery entirely: reconciliation is deactivate-then-activate with a rollback. Tiers 2 and 3 are documented and deliberately unimplemented.
6. **Phases 13, 14 and 15 do not exist** in the source document's numbering — it runs Phase 12 (waves), then Phase 16 (enforcement), then Phase 17 (HMR). This plan preserves those numbers rather than renumbering, so every cross-reference keeps working.
